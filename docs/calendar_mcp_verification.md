# Google Calendar MCP疎通確認手順書

*対象：Telegram経由の自然文で、Claude CodeがGoogle Calendar公式remote MCPサーバーを通じて予定の照会・登録・変更・削除を正しく行えるかを手動で確認する（Issue #4）*
*実施者：弘晃さん（OAuth設定完了後に実施。Kilo Codeへの依頼範囲には含めない）*
*本書作成時点（2026-10-27）ではOAuth設定が未完了のため、本書の手順は未実施*

## 0. 前提条件

以下がすべて揃ってから着手する。

- [ ] WSL2（Ubuntu）上でClaude Codeが`--channels plugin:telegram@claude-plugins-official`付きで起動しており、Telegramのペアリングが完了している（`docs/wsl2_migration.md`参照）
- [ ] Google Calendar公式remote MCPサーバーがClaude Codeのカスタムコネクタとして登録され、OAuth認可が完了している（要件定義書 6章 手順6）
- [ ] Claude Code上で`/mcp`を実行し、Google Calendarのサーバーが`connected`と表示される
- [ ] 確認作業を行うGoogleアカウント・カレンダーを決めておく（下記「テストデータの扱い」参照）
- [ ] Google CalendarをPCブラウザまたはスマホアプリで開き、目視確認できる状態にしておく
- [ ] Google Calendarのタイムゾーン設定が「(GMT+09:00) 日本標準時」であることを確認しておく

### テストデータの扱い

- テストで登録する予定のタイトルには、必ず先頭に`【疎通テスト】`を付ける。実在の予定と取り違えないため、また後片付けで検索しやすくするため
- 可能であればテスト専用のサブカレンダー（例：`ナルエビ疎通テスト`）を作成し、そこで実施する。メインカレンダーで行う場合は、変更・削除ケースで**実在の予定を対象にしない**こと
- 変更・削除ケースの事前準備として、下記「4. 変更・削除」の準備用予定を**Google Calendar側で手動登録**しておく（登録ケースの結果に依存させないため）

### 記録方法

各ケースについて、本書末尾の「7. 結果記録表」に OK / NG / 保留 と気づいた点を記入する。NGの場合はTelegram上のやり取りのスクリーンショットと、Google Calendar側の状態を控えておく。

## 1. 共通の期待動作（全ケース共通）

各ケースの「期待される動作」に加えて、以下を全ケースで確認する。

| # | 観点 | 期待される動作 |
|---|---|---|
| C-1 | 応答経路 | 返信がTelegram上に返ってくる（WSL2側のターミナルにだけ出て終わらない） |
| C-2 | 実データ参照 | 回答内容がGoogle Calendarの実データと一致する（推測・捏造した予定を答えない） |
| C-3 | 日時の明示 | 相対表現（「明日」「来週の月曜」等）を解釈した場合、解釈後の**具体的な日付（曜日付き）**を返信に含める |
| C-4 | タイムゾーン | 時刻が日本時間（JST）で扱われ、9時間ずれ等が起きない |
| C-5 | 書き込み前の確認 | 登録・変更・削除の前に、対象と内容を提示して実行してよいか確認を求める（少なくとも削除と、対象が曖昧な変更では必須） |
| C-6 | 書き込み後の報告 | 登録・変更・削除の実行後、実行した内容（タイトル・日時）を報告する |
| C-7 | 委任しない | Google Calendar操作をKilo Code（`kilo run`）に委任せず、Claude Code自身がMCP経由で実行する（要件定義書 4.2 の例外規定） |

> C-5 について：本プロジェクトは`--dangerously-skip-permissions`で稼働するため、Claude Code側のツール実行確認プロンプトは出ない。誤削除を防ぐ歯止めは「Telegram上でナルエビちゃんが確認を求めること」のみになる。確認なしで削除が実行された場合はNGとして記録し、運用ルール（CLAUDE.md等）への追記を検討する。

| Q-9 | 再来月の15日の予定は？（予定を入れていない日） | 予定がないことを明示する。エラーや無応答にならない | 該当日に予定が本当にないか |

## 5. 異常系（任意）

余裕があれば実施する。OAuthやMCP接続の問題を切り分けるためのケース。

| ID | 操作・入力 | 期待される動作 | 確認方法 |
|---|---|---|---|
| E-1 | Claude Code側で`/mcp`からGoogle Calendarを一時的に切断した状態で「明日の予定を教えて」 | カレンダーに接続できない旨を正直に伝える。予定を推測・捏造して答えない | Telegramの返信内容のみ確認（Google Calendar側の変化なし） |
| E-2 | boot.shによる再起動（Claude Codeプロセスの異常終了→5秒後の自動再起動）後に「今日の予定は？」 | 再起動後もMCP接続が維持され、正しく応答する。再認可が必要な場合はその旨を伝える | Q-2と同様に予定が一致するか |

## 6. 後片付け

1. Google Calendarの検索欄で`【疎通テスト】`を検索し、残っているテスト予定をすべて削除する（繰り返し予定は「すべての予定」を選んで削除）
2. テスト専用のサブカレンダーを作成した場合は、カレンダーごと削除してもよい
3. E-1で切断したMCP接続を元に戻し、`/mcp`で`connected`を確認する
